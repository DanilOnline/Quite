# Quiet — мінімалістичний launcher для iPhone

Самостійна реалізація за принципом Dumbify, з власною назвою та кодом.
Версія 0.1. Код підготовлено, але не скомпільовано в Xcode і не перевірено на iPhone.
Це проєкт застосунку, НЕ готовий інсталяційний IPA. Точна відповідність Dumbify не підтверджена.

## Що реалізовано
- Нативний застосунок SwiftUI для iOS 17+.
- Текстові середній (3 пункти) і великий (8 пунктів) віджети WidgetKit.
- Додавання, видалення, перейменування, редагування та перестановка пунктів.
- Темна, світла та системна теми; розмір, жирність, курсив, вирівнювання.
- Збереження налаштувань у спільному App Group; запит оновлення віджета після змін.
- Відкриття URL або команди Shortcuts за назвою, повідомлення при невдалому відкритті URL.
- Інструкція першого налаштування українською. Немає реклами, аналітики або сервера.

## Якщо є лише Windows
Windows підходить для редагування коду. Для компіляції iOS потрібні Xcode і macOS — можна використати хмарний Mac.
У комплекті є GitHub Actions, який виконує перевірку компіляції на macOS без власного Mac:
1. Створіть репозиторій GitHub.
2. Завантажте ВМІСТ папки Quiet у корінь репозиторію, включно з прихованою папкою .github.
3. У Actions запустіть Check iOS build. Для приватних репозиторіїв перевірте доступні хвилини та тарифи GitHub.
4. Результат — збірка для СИМУЛЯТОРА. Її НЕ можна встановити на iPhone.
Цей workflow ще не запускався. Якщо є помилка, надішліть журнал збірки для виправлення.

## Як отримати застосунок на iPhone
Найпряміший офіційний шлях з Windows — хмарний Mac + ваш Apple Developer Program + TestFlight.
Це окремий етап: підпис, реєстрація ідентифікаторів і App Group, архівування та завантаження.
Не купуйте підписку до успішної компіляції та визначення способу встановлення.
Паролі Apple та сертифікати не потрібно надсилати в чат або класти до репозиторію.

На Mac із Xcode і Homebrew:
```
brew install xcodegen
cd Quiet
xcodegen generate
open Quiet.xcodeproj
```
Перед збіркою для телефона:
1. Замініть com.example.quiet та com.example.quiet.widget у project.yml на власні унікальні Bundle IDs.
2. Замініть APP_GROUP на власний зареєстрований group.… ідентифікатор.
3. Згенеруйте проєкт знову. Для обох targets виберіть ту саму Apple Developer Team у Signing & Capabilities.
4. Зареєструйте спільний App Group для ОБОХ targets; інакше віджет не отримає налаштування.
5. Запустіть на підключеному телефоні або виконайте Product → Archive → Distribute App → App Store Connect.
6. Налаштуйте застосунок в App Store Connect і внутрішнє тестування TestFlight; встановіть через TestFlight на iPhone.
Доставка через TestFlight потребує членства Apple Developer Program. Зовнішнє тестування може потребувати перевірки Apple.
Без облікового запису, ідентифікаторів і підпису цей комплект самостійно нічого не встановлює.

## Після встановлення
1. У «Командах» створіть Quiet Phone з дією «Відкрити програму» → «Телефон».
2. Так само створіть Quiet Messages, Quiet Maps, Quiet Music, Quiet Camera, Quiet Notes — або змініть назви в Quiet.
3. Перевірте кожну команду вручну. Quiet не створює команди автоматично.
4. Додайте великий віджет Quiet на головний екран.
5. Оберіть однотонні чорні/білі шпалери. Приберіть зайві іконки й Dock вручну.
6. Для інших застосунків використайте команду «Відкрити програму» або відомий URL застосунку.

## Межі реалізації
- iOS керує головним екраном, відступами, підписами, Dock та оновленням віджетів.
- Запуск віджета проходить через Quiet; для команд додатково використовується Shortcuts. Можливі видимі переходи.
- Немає автоматичного переліку всіх установлених програм, блокування програм чи приховування сповіщень.
- Системне тонування віджетів може змінювати кольори.
- Список більший за ліміт віджета зберігається, але зайві пункти не показуються; перемістіть потрібні вище.
- Відсутню команду Shortcuts обробляє сама програма «Команди».
- Немає імпорту налаштувань Dumbify. Без скриншотів порівняння піксель у піксель неможливе.

## Перевірка перед щоденним використанням
Зібрати обидва targets; перевірити запуск на iPhone, передачу даних App Group,
відкриття кожної команди, помилковий URL, перейменування/видалення та перестановку,
обидва розміри віджетів, теми, перезапуск телефона й довгі назви.
У цьому середовищі перевірено структуру конфігурації та архіву; runtime-перевірка не виконана.
